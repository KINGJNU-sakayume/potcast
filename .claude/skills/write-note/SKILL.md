# 노트 쓰기

ARC Music의 노트는 손으로 쓴 글이다. 사용자가 디스코그래피를 순서대로 훑으며 읽는 글이므로, 한 장의 앨범을
**그 아티스트의 경력 안에 놓고**, 한 곡을 **그 앨범 안에 놓고** 읽게 하는 것이 목표다. 근거 없는 내용으로
빈자리를 채우지 않되, 맡은 범위는 끝까지 채운다.

기준이 되는 노트: 아티스트 `notes/artists/david-bowie.md`, 앨범 `notes/albums/ziggy-stardust.md`.
곡 노트는 이 스킬의 기준(§3)이 보위 곡 노트보다 높다. 보위 곡 노트의 **구조**(곡을 시간 순으로 따라가는 청취 포인트 →
목소리·화자 → 앨범 속 위치)를 따르고, **분량과 깊이**는 §3의 기준을 따른다.

## 0. 작업 순서 — 한 번의 요청이 끝나는 지점

"아티스트 A의 앨범 B 노트를 써 줘"는 앨범 노트 하나가 아니라 아래 네 단계를 **모두** 끝내야 완료다. 곡 노트나
아티스트 노트를 요청받았을 때도 같은 순서로 위쪽(아티스트, 앨범)이 기준을 채우는지 먼저 확인한다.

1. **아티스트 노트** (`notes/artists/<A>.md`): 없으면 쓴다. 있지만 `npm run notes:audit -- artists/<A>`가 기준 미달로
   표시하면(또는 `PENDING_REVIEW`에 있으면) 기준에 맞게 보강한다.
2. **앨범 노트** (`notes/albums/<B>.md`): 리뷰 본문과 함께 frontmatter에 `tracks:`(표준판 수록곡의 곡 노트 키를
   수록 순서대로)를 적는다. 디럭스판 보너스 트랙은 사용자가 원할 때만 넣는다.
3. **수록곡 전부의 곡 노트**: `tracks:`의 모든 곡. 대표곡 몇 개만 쓰거나 인터루드를 건너뛰지 않는다. 앨범 노트와
   곡 노트의 해석이 서로 맞게, 앨범 노트를 먼저 쓰고 곡 노트를 쓴 다음 앨범 노트의 '트랙 읽기'를 다시 확인한다.
4. **번역**: 곡의 **가사 언어**로 정한다(아티스트의 국적이 아니다). 판별은 `translate-lyrics` 스킬 §0의 기준을 따른다.
   - 가사의 주된 언어가 한국어가 아닌 곡(일본어·영어·중국어 등 외국어 곡. 가사가 전부 영어인 K-pop 곡도 여기 속한다)은
     `translate-lyrics` 스킬로 번역까지 한다. 번역이 있어야 곡 노트가 완성된다(화자·청자 해석이 감상 본문과 번역 브리프에 같이 들어간다).
   - 가사의 주된 언어가 한국어인 곡은 **영어 후렴·영어 한두 줄이 섞여 있어도 번역하지 않는다.** `translation:` 블록,
     `## 번역에 대하여`, `.translation.json`을 만들지 않고 `lyricsLanguage: ko`를 적는다. 번역 섹션이 없는 만큼
     감상 본문의 가사·화자 문단이 가사를 읽어 내야 한다(§3의 한국어 곡 기준).
   - 연주곡이면 `lyricsLanguage: instrumental`.

분량이 커서 여러 커밋으로 나누는 것은 괜찮다. 그때는 끝낸 것과 남은 곡을 사용자에게 분명히 알리고, 남은 곡을
"완료"라고 보고하지 않는다. 요청 범위 밖(같은 아티스트의 다른 앨범 등)은 쓰지 않는다.

### 기존 노트가 있을 때

- `src/editorial/notes/{artists,albums,songs}/*.md`에 이미 있으면 새 파일을 만들지 말고 그 파일을 고친다.
- 기준(§3, `npm run notes:audit`)을 채우는 노트는 사용자가 다시 쓰라고 하지 않는 한 기존 문장을 바꾸지 않는다
  (추가·보강은 가능, `updated` 날짜 갱신).
- **기준 미달 노트는 다시 쓴다.** `src/editorial/quality.ts`의 `PENDING_REVIEW`에 있는 노트가 그렇다. 다시 쓴 뒤
  `PENDING_REVIEW`에서 그 줄을 지운다(통과한 노트가 목록에 남아 있으면 테스트가 실패한다). 번역 부분(`translation:`
  블록, `## 번역에 대하여`, `.translation.json`)은 §3의 곡 노트 규칙대로 보존하거나 기준에 맞춰 보강한다.
- 앨범·곡 노트의 `artist`는 `notes/artists/` 파일 이름(키)이어야 한다.
- 같은 아티스트의 다른 노트를 읽고 앞뒤 내용과 어긋나지 않게 한다(예: 전작 노트에서 한 말과 모순되지 않게).

## 1. 대상과 Spotify ID 확인

- 노트는 Spotify ID로 먼저 매칭되고, 없으면 제목과 아티스트 이름으로 매칭된다(`src/editorial/lookup.ts`).
- 사용자가 준 `open.spotify.com/album/<ID>` / `track/<ID>` / `artist/<ID>` 링크의 22자 ID를 쓴다. 링크가 없으면
  웹 검색으로 찾는다. 확실하지 않은 ID는 넣지 말고 제목 fallback에 맡긴다.
- 한 릴리스에 ID가 여러 개인 경우가 많다(디럭스판, 지역판, 싱글 수록판). 아는 것은 모두 넣는다.
- `titles` / `names`에는 Spotify가 보여줄 수 있는 모든 표기를 넣는다: 원어, 로마자, 영어, 한국어
  (`[感電, Kanden]`, `[Kenshi Yonezu, 米津玄師, 요네즈 켄시]`). 앨범에는 `releaseYear`를 넣는다.

## 2. 조사

WebSearch / WebFetch로 확인한 사실만 쓴다. 조사할 것:

- 발매일, 레이블, 프로듀서·편곡·참여 아티스트, 수록곡과 선공개 싱글, 타이업(드라마·애니메이션·광고)
- 아티스트 인터뷰, 라이너 노트, 제작 과정에 대한 본인의 말
- **디스코그래피 속 위치**: 직전·직후 릴리스, 그 사이에 바뀐 것(사운드, 협업자, 레이블, 개인사), 반응과 성과
- **곡마다** 그 곡을 다룬 자료: 작곡·녹음에 대한 아티스트·프로듀서 인터뷰, 곡 단위 리뷰나 해설, 뮤직비디오,
  공연 영상. 앨범 위키 문서 하나로 열여덟 곡을 쓰지 않는다.
- 의견이 갈리는 부분은 출처를 확인해 "~라는 평이 있다"처럼 쓰지 말고, 근거를 들어 직접 판단하거나 뺀다.

출처 규칙:

- **위키피디아와 나무위키는 출발점일 뿐 유일한 출처가 될 수 없다.** 한국 음악은 나무위키가 가장 촘촘하고 위키피디아는
  거의 없지만, 둘 다 누구나 편집하고 출처 없는 서술이 섞여 있다. 사실 확인과 단서 찾기에 쓰고 `sources`에 올릴 수는
  있어도 **독립 출처로 세지 않는다.** 나무위키는 CC BY-NC-SA이므로 문장을 가져오지 않고, 확인한 사실만 자기 문장으로 쓴다.
  노트마다 위키피디아·나무위키·Spotify가 아닌 출처(공식 사이트, 인터뷰, 라이너 노트, 평론·기사)를 하나 이상 둔다.
  출처는 노트마다 2개 이상. `quality.ts`의 `SECONDARY_SOURCE`가 이 규칙을 검사한다.
- **한국 음악의 출처**: 해외 매체가 다루지 않는 곡이 많다. 아티스트·소속사 본인의 발언이 담긴 국내 매체의 인터뷰·쇼케이스
  기사(텐아시아, 뉴스1, 한국일보, 스타뉴스, 뉴시스 등), 공식 크레디트·앨범 소개, 영어 매체의 K-pop 인터뷰(NME,
  Billboard, Hollywood Reporter 등)를 쓴다. 접근 가능 여부는 환경마다 다르다. VIBE·한겨레·중앙일보·연합뉴스는 차단,
  멜론은 robots.txt로 막혀 있고 weiv·리드머는 읽히지 않는 것을 확인했다(2026-10 기준). 읽히지 않는 곳을 지어서 인용하지 않는다.
- **독립 출처를 찾지 못하면 채워 쓰지 않는다.** 그 곡·앨범은 하한 미달로 두고, 무엇이 부족해 멈췄는지를 완료 보고에 적는다.
  크레디트·가사 정보만으로 소리 문단을 지어내는 것은 분량을 채우는 방법이 아니다.
- 참고한 자료는 `sources`에 남긴다(URL 또는 "잡지명, 호, 연도" 같은 표기). 확인하지 못한 사실(차트 순위,
  판매량, 날짜)은 쓰지 않는다.
- 듣지 않고 쓸 수 있는 정보(크레디트, 기록)는 출처에서 오지만, 노트의 중심은 **소리에 대한 서술**이다. 어떤
  구간에서 무엇이 들리는지는 공식 음원·뮤직비디오·공연 영상, 그리고 그것을 구체적으로 묘사한 리뷰와 인터뷰로
  확인한다. 확인하지 못한 소리(악기, 구간 구성)를 지어내지 않는다.

## 3. 쓰기

### 공통 문체

- 한국어 평론체, **'~다'로 끝나는 평서문**. 1인칭("나는", "필자는")은 쓰지 않는다.
- 주장에는 구체적인 근거를 붙인다: 곡 제목, 구간(인트로·브리지·마지막 후렴), 악기와 질감, 가사의 이미지, 트랙 순서.
- 상투어·홍보 문구 금지: "명반", "전설적인", "귀를 사로잡는", "역대급", "완성도 높은" 같은 말 대신 무엇이
  어떻게 좋은지 쓴다. 과장된 수사, 영어 단어 남용도 피한다.
- 앨범·곡 제목은 『앨범』, '곡' 표기를 쓴다. 고유명사는 처음 나올 때 원어를 괄호로 병기할 수 있다.
- 가사 인용은 분석에 꼭 필요한 짧은 구절(몇 단어)만. 가사 전체나 여러 줄을 옮기지 않는다.
- 점수·별점은 쓰지 않는다.

### 앨범 — 평론가형 리뷰

`short`(페이지에 보이는 프리뷰): 2–3줄, 약 80–130자. 이 앨범을 한 문장으로 규정하는 핵심 주장.

본문(`full`): 약 1,800–3,500자(1,800자 미만은 기준 미달). 아래 흐름을 기본으로 하되, 앨범에 맞게 줄이거나 합친다. `##` 소제목은 긴 리뷰에서만
쓰고 2–4개 정도로 둔다(짧은 리뷰는 소제목 없이 문단만).

1. **리드**(소제목 없음): 이 앨범이 무엇을 하려 했고 실제로 무엇을 해냈는지.
2. **배경**: 발매 시점, 아티스트 경력에서의 위치, 전작에서 무엇이 바뀌었는지.
3. **사운드와 구성**: 프로덕션, 편곡, 시퀀싱(곡 순서가 만드는 흐름), 앨범을 관통하는 모티프.
4. **트랙 읽기**: 앨범의 성격을 보여주는 2–4곡을 구체적으로. 모든 곡을 나열하지 않는다.
5. **가사와 주제**: 반복되는 이미지와 화자, 앨범이 붙드는 질문.
6. **디스코그래피 속에서**(마지막): 이 앨범이 남긴 것, 다음 작품으로 무엇이 이어지는지, 함께 들을 앨범.
   평가는 여기서 분명하게 하되 점수 없이 문장으로.

### 아티스트 — Editorial Note

- `origin`: `도시, 나라 · 역할` 형식의 한 줄(예: `Tokushima, Japan · singer-songwriter / producer / illustrator`).
- `short`: 2–3줄, 이 음악가를 듣는 관점.
- 본문: **1,200자 이상**. 경력을 **시기(era)** 로 나눠 디스코그래피의 흐름을 보여준다. 시기마다 대표 앨범과 무엇이 달라졌는지.
  끝에 "처음 듣는다면" 들어갈 앨범을 제안할 수 있다. 소제목(`## 초기 (2012–2015)` 등)을 써도 된다.
- `eras`(필수): 본문의 시기 구분을 frontmatter에도 적으면 Artist 페이지의 디스코그래피 타임라인에 시기 표시가 붙는다.
  한 줄에 하나, `연도–연도 · 짧은 이름` 형식으로 쓴다. 진행 중인 시기는 끝 연도를 비우고(`2018– · …`), 한 해짜리는
  연도 하나만 쓴다. 이름은 10자 안팎으로 짧게, 본문과 같은 구분을 쓴다. 근거가 분명한 전환점(데뷔, 활동명 변경,
  레이블 이적, 결정적인 히트)만 시기로 나눈다.

  ```yaml
  eras:
    - 2009–2011 · 하치(ハチ), 보컬로이드 프로듀서
    - 2012–2017 · 『diorama』부터 직접 노래하기
    - 2018– · 'Lemon' 이후
  ```
- `discography`(선택): 앨범 페이지의 이전/다음 순서를 직접 정한다. 정규작 순서대로 한 줄에 하나, 발매 제목
  (모든 에디션에 맞는다) 또는 Spotify 앨범 ID를 쓴다. 목록에 없는 앨범(라이브 앨범, 앨범으로 분류된 편집반)은
  건너뛴다. 목록에 없는 앨범 페이지에서는 기존처럼 발매일 순서를 쓴다. 아티스트 페이지 타임라인은 바뀌지 않는다.

  ```yaml
  discography:
    - The College Dropout
    - Late Registration
    - Graduation
  ```

  (Late Registration 다음이 라이브 앨범 Late Orchestration이 아니라 Graduation이 된다. frontmatter에는 줄 끝 주석이 없으니
  목록 항목 뒤에 `#`을 붙이지 않는다.)
- `image`(선택): 아티스트 사진 URL(https). 앨범 노트의 `cover`(선택)도 같은 방식으로 Archive 카드의 커버가 된다. Archive 머리에 보인다. 없으면 Spotify에 연결됐을 때 Spotify 사진을,
  아니면 모노그램을 보여준다. `npm run notes:art`가 비어 있는 `image`/`cover`를 채운다.

### 곡 — Listening Note (곡 하나에 노트 하나)

곡 노트는 Now Playing에서 곡을 들으며 읽는 글이다. 그 곡을 처음 듣는 사람이 **노트를 읽은 뒤 같은 곡을 다시
들었을 때 전에 듣지 못한 것을 듣게** 만드는 것이 목표다.

- `short`: 1–2줄, 약 60–110자. 리뷰가 아니라 **어디를 들어 보라는 구체적인 신호**(구간, 악기, 목소리의 변화).
- 감상 본문: **3–5문단, 600–1,000자**(공백 포함, `## 번역에 대하여` 제외). 소제목은 쓰지 않는다.
  **`lyricsLanguage: ko`인 한국어 곡은 4–6문단, 900–1,500자**다(`quality.ts`의 `koSongBody` 900, `koSongParagraphs` 4).
  번역과 `## 번역에 대하여`가 없는 곡이므로 늘어난 분량은 아래 3번 문단(가사와 화자)이 채운다. 문단마다 하는 일:
  1. **청취 포인트** — 곡을 시간 순서로 따라간다. 인트로·절·후렴·브리지·아웃트로에서 무엇이 들어오고 빠지는지,
     악기와 질감, 목소리(음역, 팔세토, 겹친 화음, 이펙트)가 어떻게 바뀌는지. 가장 긴 문단이다.
  2. **만든 방식** — 누가 어떻게 만들었는지가 **소리에 어떻게 드러나는지**. "X가 프로듀싱했다"에서 끝내지 않고
     그 사람의 방식이 이 곡의 어느 부분을 만들었는지까지 쓴다. 샘플·인용이 있으면 원곡의 무엇을 가져와 어떻게
     바꿨는지.
  3. **가사와 화자** — 누가 누구에게 무엇을 말하는지, 핵심 이미지, 곡 안에서 바뀌는 태도. 번역 브리프
     (`translation.speaker` / `addressee` / `situation`)와 같은 해석이어야 한다.
     **한국어 곡**은 번역이 없으므로 이 문단을 두 문단으로 나눠도 된다. 화자·청자·상황과 곡 안에서 바뀌는 태도, 반복되는
     이미지, 말투(반말·존댓말, 호칭)가 곡의 어디서 바뀌는지를 쓰고, 영어 구절이 섞여 있다면 어느 자리에 왜 들어갔는지
     (후렴의 훅인지, 한국어 문장과 의미가 맞서는지)를 쓴다. 인용은 몇 단어까지만이고, 원문 가사는 저장소에 쓰지 않는다.
  4. **앨범 속 위치** — 앞뒤 곡과의 연결, 앨범 노트의 논지에서 이 곡이 맡은 자리, 디스코그래피의 다른 곡과의 연결.
  짧은 곡(인터루드)도 같은 기준이다. 길이가 짧은 이유, 앞뒤 곡 사이에서 하는 일, 참여자의 목소리를 쓴다.

**좋은 예**: `notes/songs/five-years.md`, `notes/songs/rock-n-roll-suicide.md`의 구조(편곡이 커지는 과정과
화자의 거리 변화가 같은 방향으로 움직인다는 관찰, 앨범의 처음과 끝을 잇는 문단).

**안 되는 예** (이전 『Starboy』 곡 노트에서 실제로 나온 것):

- 사실 나열: "템포는 93BPM이고 A마이너로 쓰였으며, 30분 만에 썼다", "세 번째 핫 100 1위". 수치·기록은 소리나
  해석과 연결될 때만 쓴다.
- 크레디트 나열: "A, B, C, D가 프로듀싱한 곡이다"로 시작하고 끝나는 문단.
- 전언: "~라는 평이 있었다", "~라고 전해진다". 근거를 들어 직접 판단하거나 뺀다.
- 결론 없는 권유: "~에 귀를 두고 들어 볼 만하다"로 끝나고 무엇이 들리는지는 쓰지 않는 문단.
- 위키피디아 문서 하나만 `sources`에 둔 노트.

곡 노트는 큐레이션 번역도 담는다(`translate-lyrics` 스킬):

- frontmatter의 `translation:` 블록, 본문 끝의 `## 번역에 대하여` 섹션(예약된 제목이다. 감상 본문에 같은 제목을
  쓰지 않는다), 같은 이름의 `<key>.translation.json` 파일이 한 벌이다.
- 감상 본문은 `## 번역에 대하여` **위에** 쓴다.
- 기존 번역이 기준을 채우면 그대로 보존한다. `## 번역에 대하여`가 150자 미만이거나 감상 본문과 해석이 어긋나면
  `translate-lyrics` 기준대로 보강하고 `translation.updated`를 넣는다. `.translation.json`의 번역 문장은 원문과
  대조해 고칠 때만 바꾼다.
- 번역만 있는 곡 노트(`short`와 감상 본문이 없음)는 미완성이다. `short`와 감상 본문을 더해 완성한다.
  곡 하나에 노트 파일을 둘 만들지 않는다.

## 4. 파일 형식

파일 이름이 키다: `src/editorial/notes/albums/stray-sheep.md` → `stray-sheep`(소문자, 하이픈).
frontmatter는 `src/editorial/frontmatter.ts`가 읽는 작은 YAML 부분집합이다: `키: 값`, `[a, b]` 목록,
`- 항목` 블록 목록, `키: >` 다음 들여쓴 줄(한 줄로 합쳐짐), 그리고 곡 노트의 `translation:` 같은 들여쓴 하위 블록.
쉼표가 든 목록 항목은 `"Tyler, The Creator"`처럼 따옴표로 감싼다.

```markdown
---
artist: kenshi-yonezu
albumIds: [052EiTRYh35MuDVJN9Emdh, 5XuZE4dvsiYEvRndrllt1t]
titles: [STRAY SHEEP]
releaseYear: 2020
cover: https://i.scdn.co/image/…
tracks:
  - kanpanella
  - flamingo
  - …
written: 2026-10-02
sources:
  - https://example.com/interview
  - "Rockin'on Japan, 2020년 9월호"
short: >
  프리뷰 2–3줄.
---

리드 문단.

## 배경

…
```

| 종류 | 필수 | 선택 |
| --- | --- | --- |
| artists | `artistIds`, `names`, `short` | `origin`, `eras`, `discography`, `image`, `written`, `updated`, `sources` |
| albums | `artist`, `titles`, `short` | `albumIds`, `releaseYear`, `cover`, `tracks`, `written`, `updated`, `sources` |
| songs | `artist`, `titles`, `short`(번역 블록이 있으면 선택) | `trackIds`, `written`, `updated`, `sources`, `translation`, `lyricsLanguage` |

위 표는 파일을 읽을 수 있는 최소 조건이다. **품질 기준**(`src/editorial/quality.ts`, `npm run check`에서 검사)은
더 엄격하다: 아티스트는 `eras`와 본문 1,200자, 앨범은 `tracks`와 본문 1,800자, 곡은 `short`·감상 본문 600자·3문단과
번역(또는 `lyricsLanguage: ko | instrumental`), `## 번역에 대하여` 150자. `lyricsLanguage: ko`인 곡은 감상 본문
900자·4문단. 모든 노트에 출처 2개 이상(위키피디아·나무위키·Spotify가 아닌 것 1개 이상), 금지 표현 없음. `trackIds`는 확인한 ID만 넣는다. 찾지 못하면 비워 두고 제목
fallback에 맡긴다(ID를 지어내지 않는다).

본문은 문단(빈 줄로 구분), `##`/`###` 소제목, `- ` 목록, `> ` 인용, `**굵게**`, `*기울임*`,
`[텍스트](https://…)`만 렌더된다(`src/components/NoteBody.tsx`). 날짜는 `YYYY-MM-DD`.

## 5. 확인하고 커밋

1. `npm run notes:audit -- <artist-key>`: 그 아티스트의 모든 노트가 기준을 채우는지 본다(길이, 문단 수, 출처,
   번역, 금지 표현, 앨범 `tracks`의 빠진 곡). `BELOW FLOOR`가 없어야 한다.
2. 스스로 점검한다. 숫자는 하한일 뿐이다:
   - 곡 노트마다 첫 문단이 곡을 시간 순서로 따라가며 **구체적인 구간과 소리**를 짚는가?
   - 크레디트·기록만 있고 소리와 해석이 없는 문단이 있는가?
   - 앨범 노트의 '트랙 읽기'와 곡 노트, 번역 브리프의 해석이 서로 맞는가?
   - 같은 아티스트의 곡 노트들이 같은 문장 틀("…를 따라 들어 보자")을 반복하지 않는가?
3. `npm run check`: frontmatter 오류, 없는 아티스트 키, 중복 키, 번역 짝, 그리고 품질 기준을 잡는다.
4. 미리보기 카탈로그(`/?preview`)에 있는 아티스트면 `npm run dev`로 페이지와 드로어를 확인한다.
5. 커밋 메시지 예: `notes: add STRAY SHEEP review and listening notes`. 사용자에게 무엇을 근거로 썼는지(주요 출처),
   확인하지 못해 뺀 내용, 아직 남은 곡(있다면)을 알린다.
