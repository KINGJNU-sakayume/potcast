# 팟캐스트 만들기

"앨범 A에 대한 팟캐스트"는 대본 한 파일이 아니라 아래 단계를 **모두** 끝내야 완료다. 재료는 아티스트·앨범·곡
노트와 웹 조사이고, 결과물은 `src/editorial/notes/episodes/<album>.md` 대본과 그 대본을 PR이 녹음한 목소리다.

이 스킬은 순서만 정한다. 각 단계의 규칙은 해당 스킬에 있으므로 거기를 따른다.

- 노트와 조사·출처: `write-note`
- 가사 번역: `translate-lyrics`
- 대본 형식·말투·구간·분량: `write-episode`(특히 §1의 *분량* 절)

## 0. 대상 확인

1. 아티스트와 앨범을 노트 키로 정한다. `src/editorial/notes/{artists,albums}/`에 이미 있는지 먼저 본다.
2. 노트가 없으면 Spotify ID와 표기를 `id-scout` agent로 찾는다(`write-note` §1).
3. 범위를 정한다. 기본은 **앨범 전체**다. 사용자가 "첫 세 곡만"처럼 말하면 대본 머리말에 `covers:`를 적는다.
4. 같은 앨범의 대본이 이미 있으면 새로 만들지 않고 그 파일을 고친다(`updated:`). 사용자가 "더 길게"라고 하면
   기존 대본을 이 스킬의 분량 기준으로 늘린다.

## 1. 노트 확인 — 없거나 모자라면 먼저 쓴다

1. `npm run notes:audit -- <artist-key>`를 돌린다.
2. 아티스트 노트, 앨범 노트(`tracks:` 포함), 수록곡 전부의 곡 노트, 외국어 곡의 번역 중 하나라도 없거나
   `BELOW FLOOR`면 `write-note` §0 순서대로 먼저 끝낸다.
   - 곡이 많으면 곡마다 `song-writer` agent, 번역은 `lyrics-translator` agent로 나눈다.
   - 끝나면 `note-checker` agent로 확인한다.
3. 줄 번호(`L14`)로 구간을 잡으려면 번역(`<key>.translation.json`)이 있어야 한다. 한국어 곡과 연주곡은 `m:ss`로만 잡는다.

## 2. 에피소드용 조사 — 노트에 보강한다

말 30–45분을 채우려면 노트에 있는 것보다 재료가 많아야 한다. 대본에는 출처 칸이 없고, **에피소드의 사실은
노트에서만 가져온다**(`write-episode` §0). 그래서 조사한 사실은 대본보다 노트에 먼저 들어간다.

1. WebSearch / WebFetch로 조사한다. 출처 규칙은 `write-note` §2를 따른다.
   - 위키피디아·나무위키는 출발점일 뿐이다.
   - 인터뷰, 라이너 노트, 평론·기사를 찾는다.
2. 조사할 것:
   - **앨범**: 직전 앨범과의 관계, 녹음 장소·기간·사람들, 발매 당시의 반응과 이후의 평가, 아티스트가 앨범에 대해 한 말.
   - **곡마다**: 만든 과정의 일화, 아티스트·참여자의 인터뷰 발언, 샘플·인용·영향을 준 곡, 주요 크레디트
     (피처링, 프로듀서, 연주자), 뮤직비디오·공연, 싱글이면 차트 기록.
   - **앨범 밖의 곡**: 샘플 원곡처럼 들려줄 만한 곡. 노트에 그 관계가 적혀 있어야 틀 수 있다.
3. 찾은 사실은 해당 노트에 보강한다.
   - 곡 일화는 곡 노트에, 앨범 배경은 앨범 노트에 넣는다.
   - 기준을 채우는 노트의 기존 문장은 바꾸지 않고 문단이나 문장을 **더한다**.
   - `sources`에 출처를 더하고 `updated:`를 오늘 날짜로 바꾼다.
4. 확인하지 못한 사실(출처가 하나뿐이거나 서로 어긋나는 것)은 노트에도 대본에도 넣지 않는다.

## 3. 앨범 밖의 곡

샘플의 원곡이나 영향을 준 곡을 들려줄 때는 `write-episode`의 *앨범 밖의 곡 들려주기* 절을 따른다.

- 트랙 ID는 Spotify 검색으로 실제 찾은 것만 쓴다.
- 구간은 LRCLIB 동기화 가사의 시각으로 잡는다.
- 가사가 없는 대목은 사용자에게 시간을 묻는다.

## 4. 대본 쓰기

`write-episode`를 따라 `src/editorial/notes/episodes/<album>.md`를 쓴다.

- 분량은 `write-episode` §1의 *분량* 절대로 **말 30–45분**이다. 턴을 길게 쓰지 않고 턴 수를 늘린다.
- 노트와 §2의 조사가 재료다. 같은 앨범에 이미 대본이 있으면 그 구성과 다시 듣기 구간을 살린다.
- 쓰는 동안 말의 양을 잰다(`write-episode` §5의 글자 수 명령). 한 번에 다 쓰지 말고 여는 말과 첫 두세 곡을
  쓴 뒤 잰다. 곡당 분량이 기준에 맞는지 보고 나머지를 쓴다.

## 5. 확인, 커밋, 녹음

1. `npm run check`가 통과해야 한다. 대본 문법, 구간, 말투, 턴 길이, `say:`를 잡는다.
2. 노트 보강과 대본은 따로 커밋해도 된다. 커밋 메시지 예:
   - `notes: expand IGOR notes for the episode`
   - `episodes: add STRAY SHEEP`
3. 지정된 브랜치에 푸시한다.
4. **녹음은 PR이 한다.** PR의 narration 검사가 새 대사를 Supertonic 3로 녹음하고 댓글로 보고한다.
   - PR이 열려 있어야 녹음이 생긴다. 사용자에게 이를 알리고, 원하면 PR을 연다.
5. narration 댓글을 확인한다.
   - 그 에피소드의 말 분량(``<album>`: N / N clips, M min S s``)이 30–45분 안에 드는지 본다.
   - 길이가 이상한 클립이나 목소리가 쓴 그대로 읽은 영어·숫자가 있으면 대본(`say:`)을 고친다.

## 6. 완료 보고

사용자에게 다음을 알린다.

- 새로 쓰거나 보강한 노트와 주요 출처.
- 대본의 말 글자 수와 예상 분량. narration 보고가 있으면 실제 분량.
- 다시 듣기와 앨범 밖의 곡 목록.
- **귀로 확인하지 못한 것**:
  - 가사 없는 지점의 구간
  - 앨범 밖의 곡의 구간
  - talk-over가 가사와 겹치지 않는지
  - `say:` 읽기가 자연스러운지
- 조사했지만 출처가 모자라 뺀 내용.
